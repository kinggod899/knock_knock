# knock knock 邀约

自动给代理人发邀约、走完对话二选一，每天最多 3 次。**输入用键鼠。**

## 为什么是键鼠，以及一个必须知道的坑

绝区零进程是**提权**运行的。Windows 的 UIPI 规则会挡掉低权限进程发来的键鼠事件，
所以非管理员进程看起来「游戏完全不理人」—— 这正是第一版误判成「只能用手柄」的原因。

**结论：插件必须跑在一条龙启动器里（它自带 pyuac 提权）。**
提权状态下 pynput 的键盘鼠标能直接驱动游戏，实测：按 Q 唤出 knock knock、
点 tab 切页、点列表行、点右上角 X 关闭，全都有效。

## 过期邀约（每天开跑前先清）

昨天邀约了但没赴约，今天会话里会挂一个「已过期」卡片。这时顶部**中间（会话）**
tab 图标右上角、以及左侧角色列表每一项右上角都会出现红色感叹号。不清掉这些，
进联系人列表会被卡住。

插件跑起来就是这个顺序：按 Q 唤出（默认停在会话 tab）→ 逐个清掉带感叹号的会话
→ 点左边联系人列表开始邀约。
## 流程

knock knock 只能在**录像店范围内**打开，所以脚本第一步先传送到「录像店-房间」
（复用框架的 `Transport`，和录像店营业、情报板同一套写法），再开始邀约：

0. 传送到「录像店-房间」。
1. 大世界按 **Q** 唤出 knock knock（点右下角「信息」图标是兜底）。
   **界面默认停在「会话」tab**，所以进来先点最左边的 tab。
2. 联系人列表每项两行：名字 + 状态。状态决定能不能邀：

| 状态 | 含义 | 处理 |
|---|---|---|
| `在线` / `在线...` | 今天还没邀约过 | 可以约 |
| `联络中` / `联络中...` | 今天已经邀约过 | 跳过 |

   顺序：**从列表最上面开始**，能约就约，约不了就往下选下一个，直到满 3 次。
3. 点右侧卡片的「邀约」，按结果分三路：

- **普通邀约**：进对话 → 反复点白色选项条 → 出「开始邀约同行」→ 点它。
  注意 `REPLY` 只是选项组的标签，点它没反应，要点标签下方的白色长条按钮。
- **需选时段**：出「上午/下午/夜晚/凌晨 + 加入日程」。时段是单选（带 ✓），
  脚本**四个方块依次全点一遍**（坐标固定，不用识别当前选的是哪个），最后点的生效；
  再点「加入日程」，成功后对话出现 `[待办]xxx` + 「查看日程」。
- **信赖等阶已满**：弹「和代理人已达到信赖等阶，是否继续发起邀约？」，按钮
  **取消 / 确认**，**默认焦点在「确认」上** —— 那是要消耗一次邀约的。默认点
  「取消」换下一个；在设置里勾上「达到信赖后继续骚扰代理人」才点「确认」继续。
- **次数用完**：弹「今天邀约次数已用完」，只有**一个「确认」按钮**（在画面中间）。
  看到就直接点确认、关界面、结束——今天不会再成功了。脚本另外还会看
  左上「剩余邀约0/3」提前收工，不用等弹窗。
- **信赖卡在等阶满值**：弹「信赖已到达当前等阶满值，是否进行升阶事件？」，按钮
  **取消 / 前往**。**这个只能点「取消」** —— 点「前往」会跳去升阶事件、离开邀约
  流程。两种情况长得像，判据分开（详见 WORKLOG）。

成功判据：**按流程走完即算成功** —— 结束界面出来、该点的都点过就计入成功，
不看左上「剩余邀约N/3」有没有下降。那个计数只在联系人页读得到，读不到返回 -1，
拿它判成功会把完成的邀约漏掉。它只用于「已经是 0/3 就提前收工」的兜底。

## 界面结构（实机验证，可直接复用）

顶部三个 tab（左→右）：联系人列表 / 会话 / 群聊，y 中心 283，
图标中心 x = 424 / 516 / 612。左栏列表每项两行（名字 + 状态），右栏卡片显示
代理人印象 + 「邀约」按钮。列表可滚动，**行位置靠 OCR 实时定位再点**，
不做成固定坐标。

## 代码结构

```
plugins/knock_knock/            仓库根（github.com/kinggod899/knock_knock）
├── knock_knock/                插件包，目录名 = APP_ID，整体打进 zip
│   ├── app.py                  状态机（15 节点 / 29 条边），键鼠输入层
│   ├── screen.py               画面常量 + 实机标定值（含提权说明）
│   ├── config.py               配置
│   ├── factory.py              工厂
│   ├── const.py                APP_ID 等
│   ├── app_setting.py          设置入口声明
│   ├── setting_flyout.py       设置弹窗
│   ├── plugin.json             插件市场元数据
│   └── __init__.py
├── docs/                       开发文档（本文件、WORKLOG、画面建档）
└── README.md                   商店详情页展示的使用说明
```

文件名是插件商店的硬约定：`const.py` / `factory.py`（也兼容旧的 `*_const.py` /
`*_factory.py`），包目录名必须等于 `APP_ID`，`plugin.json` 的 `id` 也要一致。

## 配置

`config/<实例>/<分组>/knock_knock.yml`。在运行卡片上点齿轮可以改（FLYOUT 弹窗）。

| 键 | 默认 | 含义 |
|---|---:|---|
| `daily_invite_limit` | 3 | 一天**成功**邀约几个（游戏上限 3） |
| `max_invite_attempts` | 5 | 一天最多**尝试**几次（点几次「邀约」） |
| `continue_after_trust_full` | 关 | 信赖满级弹窗点「确认」继续，还是点「取消」换人 |

`max_invite_attempts` 比 3 大的原因：角色信赖全满、或卡着升阶任务时那些人是
点不动的。只有成功次数上限的话，脚本会一路往下把列表上所有人都点一遍。

`continue_after_trust_full` 关着（默认）就是点「取消」换下一个；开着则点「确认」
继续 —— 信赖满级只是不再涨信赖值，邀约流程本身能正常走完。


## 落点说明

`plugins/*` 在主仓的 `.gitignore` 里，插件不进一条龙主仓，独立放在自己仓库
`github.com/kinggod899/knock_knock`。本地这份就是那个仓库的工作副本，
目录本身就是仓库根（`plugins/knock_knock/.git`），主仓不会追踪它。

发版走官方模板的工作流：改 `plugin.json` 的 `version` 并把 `versionCode` 加 1，
推 `v<version>` tag，Actions 校验、打包 `knock_knock.zip` 并传 Release。
上架提交用插件市场的「提交插件」页，本仓 `README.md` 会作为详情页展示。
